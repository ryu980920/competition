# 코드 B·C 줄별 분석과 비교

Nanowire_Si_QTX SBTE(코드 B) vs NEGF(코드 C) 구조 스크립트 해설

> 두 코드는 같은 단일 GAA 나노와이어를 만드는 형제 스크립트입니다. 이 문서는 원본 코드를 그대로 인용하지 않고, 실행 순서(위→아래)를 따라 각 블록이 하는 일을 말로 풀어 설명한 뒤, 마지막에 두 코드의 차이를 표로 정리한 분석 노트입니다. 원본은 학교 라이선스로만 열람 가능합니다.
>
> B = Nanowire_Si_QTX_SBTE (기능이 많은 버전) · C = Nanowire_Si_QTX_NEGF (단순 버전)

## 1. 헤더 · 재료 정의 블록

**코드 B**는 맨 위에서 Synopsys 검증 확산·활성화 모델 세트(AdvancedCalibration)를 먼저 로드해 도핑 정확도를 확보하고, 내부 좌표계를 DF-ISE 규약으로 고정합니다. 이어서 소스/드레인용 태그 재료를 KMC(원자단위 시뮬레이션)에서도 인식되도록 옵션을 붙여 생성하고, Low-k 스페이서 재료도 함께 등록합니다. 채널·소스드레인 재료와 도핑값은 `set`으로 변수에 저장합니다.

**코드 C**는 AdvancedCalibration과 좌표계 설정이 헤더에 없습니다 — C는 이걸 뒤(확산 직전)에서 한 번만 부릅니다. 재료 등록에서도 KMC 관련 옵션이 빠져있습니다(C는 KMC를 안 쓰기 때문). 변수 선언도 `set`이 아니라 `#define`(매크로)으로 합니다 — 기능은 같고 표기 방식만 다릅니다.

> **차이 요지**: B는 시작부터 캘리브레이션·좌표계·KMC 준비를 다 해두는 "풀옵션" 헤더, C는 그걸 덜어낸 "경량" 헤더.

## 2. 사용자 함수 · 라이브러리 블록

**코드 B**는 외부 TCL 함수 파일 하나만 불러옵니다.

**코드 C**는 그 파일 외에 폴리헤드론 도우미 함수 라이브러리를 추가로 불러오고, 디버그 시 구조를 단계별로 번호 붙여 저장하는 함수를 자체적으로 정의합니다(B에는 없음).

> **차이 요지**: C가 디버그 편의 함수와 추가 라이브러리를 갖춘 반면 B는 더 간결. 단, B는 뒤에서 KMC 등 다른 방식으로 기능을 채웁니다.

## 3. 구조 치수 · 제약 · 파생좌표 블록 (B·C 거의 동일)

이 블록은 B와 C가 사실상 동일합니다. 지름/폭/높이 같은 치수 파라미터를 Workbench에서 받아오고, 원형 단면 선택 시 지름과 다른 치수가 서로 맞는지 정합성을 강제하며, 이후 도형을 그릴 경계 좌표를 미리 계산합니다. 사다리꼴 측벽 기울기는 아랫변·윗변·높이로 삼각함수를 이용해 계산해, 실제 식각 공정의 기울어진 단면을 반영합니다.

## 4. 메시 라인 정의 블록 — 좌표축이 다름

**코드 B**는 x축을 채널 길이 방향으로 두고, 길이 방향 메시를 여러 구간(소스 경계, 게이트 경계, 중앙 등)으로 세분해 촘촘하게 정의합니다. 단면 방향(y, z축)도 별도로 정의합니다.

**코드 C**는 z축을 채널 길이 방향으로 두고, 길이 방향 메시 구간을 B보다 적은 개수로 성기게 정의합니다. 단면 방향은 y, x축입니다.

가장 실무적으로 중요한 차이: **B는 채널 길이 = x축, C는 채널 길이 = z축**입니다. 좌표 규약이 반대라 두 코드를 섞어 참고할 때 축을 헷갈리면 안 됩니다. 또한 B가 C보다 길이방향 메시 라인을 더 촘촘하게 나눕니다.

> **차이 요지**: 같은 나노와이어라도 B는 x-길이/더 촘촘, C는 z-길이/더 성김. SDevice에서 전극·단면을 뽑을 때 이 축 차이를 반드시 반영해야 함.

## 5. 구조 생성 블록 (원형 단면 모드)

**코드 B**: 임시 재료로 전체를 채운 뒤, 원통(X축 기준)으로 게이트 산화막 → 채널 실리콘 → 소스/드레인 → Low-k 스페이서 순서로 안쪽부터 겹겹이 만듭니다. 이 파일에는 게이트 금속 생성 코드가 아예 없습니다.

**코드 C**: 같은 순서를 원통(Z축 기준)으로 만듭니다. 채널 영역 이름이 B와 다르게 지정됩니다. 게이트 금속(Tungsten) 생성 코드가 존재하지만 비활성화 상태로 남아있습니다.

- 만드는 순서·구조는 동일: 바깥부터 게이트산화막 원통 → 채널 실리콘 원통 → S/D 원통 → LowK 스페이서.
- 원통 축이 다름: B는 X축, C는 Z축(4장의 좌표규약과 일치).
- 채널 영역 이름이 B·C에서 서로 다르게 붙어있음 — SDevice에서 영역명을 참조할 때 주의해야 합니다.
- C에는 게이트 금속 생성 코드가 비활성화된 채 존재. B에는 아예 없음. 둘 다 결과적으로 금속 없이 산화막 표면을 게이트로 사용합니다.

## 6. 도핑 · 열처리 블록 — 가장 큰 차이

**코드 B**: pMOS/nMOS 여부에 따라 채널·소스/드레인 도펀트 종류를 정한 뒤, 스위치 변수 하나로 "연속 확산"과 "KMC 원자단위 이산도핑" 중 하나를 선택할 수 있습니다. 연속 확산 모드는 800도·1100도 2단계 레이저 어닐을 씁니다. KMC 모드는 도펀트를 원자 하나하나 배치한 뒤 별도 변환 방법(Sano 방법)으로 다시 연속 농도로 환산하고, 콘택 근처 소스/드레인 농도를 추가로 보정하는 줄이 붙습니다.

- KMC 모드는 무작위도펀트요동(RDF) 편차 연구용 고급 기능입니다.
- KMC 뒤에 콘택 근처 S/D 농도를 다시 채워주는 보정 줄이 있습니다(원자단위라 콘택부 농도가 튀는 걸 방지).

**코드 C**: 같은 방식으로 도펀트 종류를 정한 뒤, AdvancedCalibration을 여기서(확산 직전) 처음 호출하고 800도·1100도 레이저 어닐만 적용합니다. KMC 분기가 없어 오직 연속 확산만 하므로 훨씬 단순합니다.

- 도펀트 종류 자체(pMOS/nMOS 분기, 소스·드레인 동일 도펀트)는 B·C 동일 — 둘 다 표준 MOSFET 방식.

> **차이 요지**: B는 연속+KMC 둘 다 가능, C는 연속만. 학부 프로젝트는 RDF까지 갈 필요 없으니 C의 단순함이 오히려 장점.

## 7. 전극 정의 · 구조 저장 블록

**코드 B**: 소스/드레인 영역을 채널 재료로 바꾼 뒤, drain·source·gate 세 전극을 box·sidewall 방식으로 명시적으로 정의합니다. 게이트는 산화막 바깥표면 전체에 잡혀 GAA의 "감싸는 게이트"를 구현합니다. 경계구조 파일과 최종구조 파일을 모두 저장합니다.

**코드 C**: 최종 순 활성 도핑 농도를 계산해 시각화 항목으로 저장하고, 최종구조 파일만 저장합니다. 마지막에 비활성화된 대체 블록(도펀트를 지우고 메시만 저장하는 경로)이 있습니다.

- B는 전극(drain/source/gate)을 명시적으로 정의. C에는 명시적 contact 정의 블록이 이 파일에 없음 — 전극 지정은 별도 파일/단계에서 처리하는 구성으로 보입니다(팀에서 확인 필요).

> **차이 요지**: B는 이 한 파일 안에서 전극까지 완결. C는 구조·도핑까지만 하고 전극은 밖에서 처리하는 모듈형. → C를 쓸 땐 전극이 어디서 정의되는지 반드시 확인해야 함.

## 9. 팀 관점 결론

- B와 C는 같은 나노와이어를 만들지만, B는 KMC·명시적 전극·촘촘한 메시를 갖춘 "연구용 풀버전", C는 그것들을 덜어낸 "입문용 경량버전"입니다.
- 학부 1개월 프로젝트라면 C로 시작 권장 — 읽고 수정할 코드가 적고, KMC 같은 무거운 기능이 없어 오류 원인을 찾기 쉽습니다.
- 단, C는 전극 정의가 이 파일에 없으므로 SDevice가 참조하는 전극이 어디서 만들어지는지 먼저 확인해야 합니다. B는 그 부분이 자기완결적이라 참고용으로 함께 열어두면 좋습니다.
- TFET 전환 필수 수정은 B·C 공통: ① 도핑 지정에서 소스=p+ / 드레인=n+로 분리, ② SDevice 물리를 classical Band2Band(NonlocalPath)로 교체, ③ 소스/드레인 비대칭으로 Ambipolar 억제. KMC(B)는 끄고 진행.
