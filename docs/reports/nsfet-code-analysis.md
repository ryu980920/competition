# NSFET_SdeviceSBTE_3nm 구조 코드 분석

3-Stack GAA 나노시트 SProcess 코드 해설 및 GAA-TFET 프로젝트 적용 방안

> 대상: 학교 Sentaurus 라이선스(AdvancedTransportPackage) 내 `NSFET_SdeviceSBTE_3nm` 프로젝트의 구조 생성 스크립트. 이 문서는 원본 코드를 그대로 인용하지 않고, 각 블록이 하는 일을 팀이 이해할 수 있게 말로 풀어 설명한 분석 노트입니다. 원본 스크립트는 학교 라이선스로만 열람 가능합니다.

## 1. 이 구조는 GAA가 맞는가

맞습니다. 스크립트 첫 줄 주석이 "3nm node 3-stack nano-slab(NS) generation"이라고 명시하듯, GAA 나노시트(Nano-Slab) 3층 스택 구조입니다. SVisual에서 보이는 3개의 얇은 막대가 적층된 실리콘 채널(나노시트)이고, 그걸 감싼 레이어가 게이트 스택(HfO2 → Oxide → 이후 금속), 맨 아래가 실리콘 기판입니다.

### 1-1. 재료와 역할

| 재료/변수명 | 구조상 위치 | 역할 |
|---|---|---|
| Silicon (기본) | 기판, 초기 전체 블록 | 구조 전체가 처음엔 통짜 실리콘으로 채워지고, 이후 다른 재료로 하나씩 치환됨 |
| SiCh (채널 태그) | 나노시트 중 채널 영역 | 물리적으로는 Silicon과 동일하지만 채널만 골라 도핑을 다르게 지정하기 위한 태그용 재료 |
| SiSD (S/D 태그) | 나노시트 양 끝, 소스/드레인 영역 | 소스/드레인만 구분하기 위한 태그용 재료. 고농도로 도핑됨 |
| Oxide | 나노시트를 감싼 얇은 안쪽 층 | 게이트 스택의 계면 산화막(SiO2 역할) |
| HfO2 | Oxide 바깥쪽 레이어 | High-k 게이트 유전체. 기본값으로 이미 들어가 있어, GAA+HKMG 자체는 이 템플릿의 베이스라인일 뿐 새로운 주제가 되기 어렵다는 판단의 근거가 됨 |
| LowK | 게이트와 소스/드레인 사이 스페이서 | 게이트-S/D 간 기생 커패시턴스를 낮추는 Low-k 스페이서 |
| Tungsten | 코드 후반부 (게이트·컨택 금속) | 게이트 전극과 소스/드레인 금속 콘택을 채우는 금속 |

## 2. 코드 블록별 상세 설명

### 2-1. 재료 정의 및 도핑 파라미터

`mater add` 명령으로 Silicon을 베이스로 하는 태그용 재료 SiCh(채널), SiSD(소스/드레인)를 새로 등록하고, `#define`으로 이후 코드에서 `_ChMat_`은 SiCh, `_SdMat_`은 SiSD로 자동 치환되게 매크로를 만듭니다. 이어서 채널 배경 도핑(약 1e15, 거의 진성 수준), 소스/드레인 도핑(약 2e20, 고농도), 채널스톱 도핑(약 3e18)을 변수로 저장합니다.

- 채널 배경 도핑이 매우 낮다는 점(거의 진성)은 흥미롭게도 TFET의 i(진성)-채널 요구조건과 이미 잘 맞습니다.
- 채널스톱 도핑은 뒤에서 기판(Silicon)에 적용되는데, 사실상 Punch-Through-Stop(PTS) 도핑입니다 — 예전에 검토했던 BDI/PTS 논의와 바로 연결되는 부분입니다.

이어지는 블록은 Sentaurus Workbench 파라미터(`@Type@`, nMOS/pMOS)에 따라 도펀트 종류(Boron/Phosphorus)를 자동으로 바꾸는 조건문입니다. **중요한 점**: 소스/드레인 도펀트가 소스와 드레인에 똑같이 적용됩니다 — 표준 MOSFET(n-p-n 또는 p-n-p) 방식입니다. TFET에 필요한 p-i-n(소스와 드레인이 서로 다른 타입)과는 다르다는 걸 기억해야 합니다. 3장에서 이걸 어떻게 고칠지 다룹니다.

### 2-2. 보조 설정

외부 TCL 라이브러리 파일 두 개를 불러옵니다(재사용 함수 모음). 디버그 스위치를 켜면 공정 단계마다 구조를 번호 붙여 저장하는 함수가 있어, SVisual로 단계별로 눈으로 확인하고 싶을 때 유용합니다. 이어서 SDE 전용 렌더링 모드를 끄는 표준 설정으로 순수 명령 기반 구조 생성 모드로 전환합니다.

### 2-3. 구조 치수 파라미터 — Workbench 스윕 변수

스택 시트 개수(nStack), 나노시트 폭(W)·두께(H), 계면 산화막 두께(tox), HfO2 두께, 채널(게이트) 길이(L), 게이트 라인 피치, 소자 간 폭방향 피치, 시트 간 수직 간격, 에피 S/D 높이, ILD 두께, 스페이서 길이, 콘택까지 거리 — 이 값들이 모두 `@...@` 형태의 Sentaurus Workbench 파라미터로 선언되어 있습니다.

**즉 이 값들은 스크립트를 고칠 필요 없이 Workbench 파라미터 표에서 숫자만 바꿔서 스윕할 수 있습니다.** 팀이 계획한 "시트 개수별 Ion 증가 확인", "치수별 트레이드오프 곡선"을 위한 스윕이 이미 이 템플릿에서 열려 있다는 뜻입니다. 스크립트를 새로 짤 필요 없이 Workbench GUI에서 nStack을 2, 3, 4로 바꿔가며 여러 노드를 만들면 됩니다.

### 2-4. 기하학적 정합성 검사

파라미터를 바꿨을 때 물리적으로 말이 안 되는 구조(예: 게이트 스택 두께가 시트 간 간격보다 커서 이웃 시트의 게이트끼리 충돌)가 만들어지는 걸 미리 걸러내는 조건문 안전장치들입니다. nStack이나 시트 간격을 스윕할 때 이 조건에 걸려 스크립트가 멈추면, 에러 메시지가 어떤 파라미터 조합이 잘못됐는지 알려줍니다.

### 2-5. 좌표 계산

시트 두께 방향, 폭 방향, 게이트 길이 방향, 스페이서 경계, 콘택 경계 등, 이후 모든 도형을 그릴 때 쓰는 좌표를 미리 계산해두는 블록입니다. 패턴은 전부 "중심 좌표 ± 절반 치수" 또는 "기준점 ± 파라미터 길이" 형태입니다. 직접 하나하나 볼 필요는 없고, 나중에 특정 경계값이 코드 뒷부분에서 어떻게 쓰이는지 역추적할 때 사전처럼 참고하면 됩니다.

### 2-6. 메시 라인 정의

x(두께 방향)·y(폭 방향)·z(채널 길이 방향) 각 축마다 위치와 그 지점 근처의 메시 조밀도를 지정합니다. 재료 경계(Oxide/HfO2/Si 경계) 근처는 촘촘하게, 재료 내부 중앙은 성기게 설정되어 있습니다. 반복문으로 이 패턴을 nStack번 반복해서, 시트가 몇 층이든 각 시트마다 동일한 메시 정밀도를 자동으로 적용합니다.

### 2-7. 시트별 반복문 — HfO2/Oxide/Si 형성

이 반복문이 스택의 핵심입니다. 시트 하나마다 ① 사각기둥(brick)으로 몸통을, ② 원통(Cylinder)으로 양 끝을 만들어 "몸통+둥근 양끝(스타디움 모양)"을 조합합니다. 이걸 HfO2 → Oxide → 채널 실리콘 순서로 안쪽을 파고들며 반복해서, 결과적으로 "실리콘 코어 - Oxide 계면층 - HfO2 고유전율층"이 겹겹이 감싼 단면이 만들어집니다.

> 참고: 예전에 검토했던 "최하단 시트만 원형(나노와이어)으로 바꾸면 전기적 제어력이 좋아진다"는 아이디어를 이 실제 템플릿과 비교해보면, 이미 모든 시트의 단면 양 끝을 원통(둥근 모서리)으로 처리하고 있습니다. 즉 순수 사각형이 아니라 "스타디움형" 단면이 업계 표준에 가깝다는 뜻이고, 그 아이디어가 완전히 틀린 방향은 아니었지만 이미 기본으로 반영되어 있어 차별화 포인트로 쓰기는 어렵습니다.

### 2-8. STI · 게이트 절연 · LowK 스페이서 · S/D 에피 · 게이트/콘택 금속

- STI: 맨 위 시트보다 더 위쪽, 폭 방향 양 끝에 Oxide 블록을 넣어 이웃 소자와 격리.
- 게이트 절연(기판 위): 스택 위쪽, 게이트 금속이 나중에 채워질 자리 중 기판과 맞닿는 부분에 HfO2·Oxide를 깔아 게이트-기판 누설 방지.
- LowK 스페이서: 게이트 길이 구간 바깥쪽부터 스페이서 길이까지 LowK로 치환 — 게이트와 소스/드레인을 분리하는 물리적 벽. 지금은 소스 쪽과 드레인 쪽에 같은 스페이서 길이가 쓰여 완전 대칭입니다.
- 스페이서 안쪽 HfO2 보강: 게이트 가장자리의 기생 커패시턴스(Fringing Capacitance)를 조절하는 부분으로, 예전에 살펴본 "Dual-k Spacer"와 개념적으로 같은 위치입니다.
- S/D 에피: 스페이서보다 더 바깥쪽을 소스/드레인 태그 재료로 채워 실제 소스/드레인 실리콘 블록 형성.
- 게이트 금속: 게이트 길이 구간, ILD 위쪽을 Tungsten으로 채워 실제 게이트 전극 형성.
- S/D 콘택 금속: 콘택 경계 바깥쪽 LowK를 Tungsten으로 치환해 소스/드레인 전극 형성.

### 2-9. 전극 정의 및 구조 저장

기판(substrate), 게이트(gate), 소스(source), 드레인(drain) 네 개의 전극을 지정하고, 여기까지의 구조(도핑 전, 순수 형상+메시)를 `.tdr` 파일로 저장합니다. 이 전극 이름들이 나중에 SDevice의 `Electrode{}` 섹션에서 그대로 참조됩니다.

### 2-10. 도핑 프로파일 적용 및 어닐링

채널·S/D 실리콘 전체에 배경 도핑을 깔아 시작점을 만든 뒤, 소스/드레인 도펀트를 erfc(여오차함수) 프로파일로 게이트 아래까지 확산시켜 넣습니다. 드레인 쪽과 소스 쪽을 나눠서 처리하지만, **둘 다 같은 도펀트를 씁니다** — 앞서 짚은 것처럼 TFET으로 바꿀 때 반드시 손대야 할 지점입니다. 채널스톱 도펀트를 기판에 적용해 PTS 도핑을 실제로 넣습니다. 마지막 열처리는 500°C·1마이크로초 수준의 매우 짧고 낮은 온도로, 3nm 노드급 초저열예산 공정을 반영한 설정입니다(도펀트를 거의 확산시키지 않고 활성화만 하는 수준).

### 2-11. 최종 저장

최종 순 활성 도핑 농도를 계산해 시각화용으로 저장하고, 도핑까지 완료된 구조를 최종 `.tdr` 파일로 저장합니다. 이 파일이 SDevice(전기 시뮬레이션) 단계의 입력이 됩니다.

## 3. 우리 프로젝트에 적용하려면

### 3-1. 이미 유리한 점

- nStack, W, H, tox, thfo2, Lg가 전부 Workbench 파라미터로 열려 있어, 멀티시트 Ion 스케일링·치수 트레이드오프 스윕을 스크립트 수정 없이 바로 진행할 수 있습니다.
- 채널 배경 도핑이 이미 낮아, TFET의 진성 채널 요구와 잘 맞습니다.
- PTS 도핑이 이미 구현되어 있어, 예전에 검토했던 BDI/PTS 방향으로 확장하고 싶다면 이 부분을 참고·비교 기준으로 쓸 수 있습니다.

### 3-2. 필수 수정 1 — p-i-n 비대칭 도핑으로 전환

가장 중요하고 반드시 해야 하는 수정입니다. 현재는 소스·드레인에 같은 도펀트가 들어갑니다. TFET은 소스와 드레인이 반대 타입이어야 합니다.

- 소스/드레인 도펀트 변수를 소스용/드레인용 두 개로 분리 (예: nTFET이라면 소스=p+, 드레인=n+).
- 도핑 지정 줄에서 드레인 쪽·소스 쪽 분기에 서로 다른 도펀트를 적용하도록 분리.
- S/D 에피 영역도 소스용/드레인용으로 나눠 서로 다른 도펀트·농도를 지정.

### 3-3. 필수 수정 2 — 소스/드레인 비대칭 설계로 Ambipolar 억제

도펀트를 분리하고 나면 자연스럽게 소스와 드레인을 다르게 다룰 수 있게 됩니다.

- 드레인 쪽 도핑 농도를 소스보다 낮게 설정.
- 스페이서 길이·콘택 거리를 소스용/드레인용으로 분리해 드레인 쪽 스페이서를 더 두껍게 설정.

### 3-4. 도전 과제 — Line-Tunneling 오버랩 구조로 전환

현재 게이트 금속은 정확히 게이트 길이 구간에만 있고, 스페이서가 그 바로 바깥부터 시작해 소스와 완전히 분리되어 있습니다(오버랩 없음 = Point-Tunneling 구조). Line-Tunneling으로 바꾸려면 소스 쪽 게이트 금속·HfO2 영역의 경계를 소스 쪽으로 오버랩 길이(Lov)만큼 더 들어간 지점까지 확장해야 합니다. 이때 소스 에피/콘택 경계는 그대로 두고 게이트/게이트 절연막 경계만 밀어 넣는 것이 핵심이라, 좌표 계산 블록(2-5)의 관련 변수들을 소스 쪽만 별도로 다루도록 재구성해야 합니다. 이 부분이 가장 손이 많이 가는 수정이고, 실제 연구자들도 어려워하는 지점이니 2주차 이후 여유 있을 때 시도하는 걸 추천합니다.

### 3-5. 잊지 말아야 할 것 — 이 파일은 구조만 만듭니다

이 스크립트는 SProcess(구조·도핑 생성) 단계만 담당합니다. Band2Band(BTBT) 물리, Nonlocal Mesh, eQuantumPotential 같은 전기적 시뮬레이션 설정은 같은 프로젝트 폴더 안의 SDevice 명령 파일(별도 파일)에 들어있고, 그 파일의 물리 모델은 현재 SBTE(양자수송)로 되어 있어 classical Band2Band(NonlocalPath) 모델로 교체해야 합니다. 이 구조 파일과 SDevice 파일은 세트로 같이 봐야 완전한 그림이 됩니다.
