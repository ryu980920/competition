## 2026-08-23 (2) — Esd 스플릿 1차 결과 무효: 구조가 안 바뀐 것으로 판단

### 판단
Esd 는 응력원과 채널 사이 가로 거리라 5→10nm 면 2배 차이다. 여기서 응력이 1 MPa 도 안 변하는 건 물리적으로 불가능하므로 **구조 자체가 안 바뀌었다**고 봐야 한다. 원인 후보:
1. `finfet_sprocess.scm` 에서 `@Esd@` 매크로가 실제 식각/구조 생성 명령에 안 쓰이고 있음 (SWB 파라미터로만 등록 → 노드는 새로 생기지만 같은 구조). FR 을 처음 추가할 때와 같은 상황
2. 언더컷이 스페이서로 제한됨 — 기존 확인 사항 중 Esd(7.5nm) < Lsp0(8nm) 라 언더컷이 스페이서 아래 머문다는 게 있었음. 다만 이 경우에도 Esd=10nm 는 스페이서를 넘으므로 뭔가 달라져야 하는데 동일한 게 걸림

## 2026-08-15 (4) — STE 정규화 판정 + 지표 체계 재정립(SSSat→SSlin/Ioff/DIBL) + 발표용 지도 6종

격자 완주 후 결론을 정리하는 과정에서 **두 개의 큰 정정**이 나왔다. 둘 다 "지금까지 쓰던 지표가 사실은 다른 걸 재고 있었다"는 종류라, 발표 결론 문장이 바뀌는 수준의 변경이다.

### 한 일 ① — STE 정규화 방법 판정 (체적평균 채택 권고)

- 8/6부터 보류해 온 숙제(체적평균 `SlFin` vs 계면 단일점 `SlFin_pt`)를 25점 전체 데이터로 판정
- **두 방식이 FR 축에서 정반대로 움직인다**: `SlFin` 피크는 5개 Ge% 모두 FR=30nm, `SlFin_pt` 피크는 모두 FR=10nm
- **결론까지 뒤집힌다**: 같은 교호작용 회귀를 두 지표로 돌리면 `SlFin` 기준은 FR 계수 -0.1225/교호작용 t=-1.57(없음), `SlFin_pt` 기준은 FR 계수 **+0.0644(부호 반대)**/교호작용 t=+2.75(있음). 즉 정규화 방법 선택이 프로젝트 결론을 바꾼다
- **판정 기준을 "어느 쪽이 이동도(gmSat)를 잘 예측하나"로 잡음** — STE는 응력이 성능으로 이어지는 효율을 재는 지표이므로. Ge% 효과를 제거하고 FR 축 안에서만 상관계수를 구하면 `SlFin` 평균 **+0.958**, `SlFin_pt` 평균 **-0.207**(음의 상관!)
- → **체적평균(`SlFin`) 채택 권고.** 단, 계면점 방식이 실패한 이유는 개념이 틀려서가 아니라 **샘플링 위치가 불완전**하기 때문으로 판단 — 이 소자는 tri-gate라 게이트 계면이 상단/양 측벽 셋인데 현재 창은 **상단만** 잡고 있다. 전류의 상당 부분이 흐르는 측벽을 놓쳤고, FR을 늘리면 SiGe가 아래·측벽 쪽으로 배치되는데 측정점은 맨 위라 오히려 값이 줄어드는 것으로 보인다. 측벽 창을 추가해 재추출하면 역전 가능성 있음(기존 tdr 재사용, 새 시뮬 불필요)

### 한 일 ② — ★ STE로 정규화하니 헤드라인 결론이 바뀜

- 절대 응력 지도는 등고선이 **수직**(Ge%가 지배)인데, STE 지도는 등고선이 **수평**(FR이 지배)으로 **정확히 90도 돌아간다**
- STE 회귀: Ge% t=**0.32(유의하지 않음, 변동폭 0.7~2.2%)**, FR t=**8.41(변동폭 10~13%)**
- 해석: Ge%는 분자(실제 응력)와 분모(명목 응력)를 같은 비율로 키우므로 **전달 "효율" 자체는 못 바꾼다.** 효율을 바꾸는 유일한 변수는 FR(0.59→0.67, 약 13% 개선)
- → 새 헤드라인: **"응력을 더 넣으려면 Ge%를, 넣은 응력을 더 잘 전달하려면 FR을 조절해야 한다"** — 두 변수의 역할이 다르다는 결론. 절대 응력만 봤다면 "Ge%가 전부"에서 끝났을 것이고, 이는 STE 프레이밍 전환(8/5)이 옳았음을 사후 증명한다

### 한 일 ③ — SSSat 지표 오용 발견 → SSlin/Ioff/DIBL 3분리

- 발단: SSSat 최솟값이 103 mV/dec라 "이 소자 못 쓰는 것 아니냐"는 우려
- **결정적 반증**: FR=0인 다섯 점은 **형상이 완전히 동일**한데(리세스 없음, Ge%만 다름) SSSat이 105→316으로 3배 벌어진다. 형상이 같은데 게이트 정전제어가 3배 나빠질 수는 없다. 같은 조건에서 SSlin은 80.4→76.6으로 거의 일정하고, `VtiWFd_100nA`/`VtiWFd_5nA` 두 전류기준으로 **독립 역산한 SS도 83.8→83.0으로 일정**
- → SSSat은 게이트 제어 기울기가 아니라 **SiGe 밴드갭 축소로 인한 드레인 접합 누설 바닥**을 함께 재고 있었음. 또한 SS의 이상한계 60 mV/dec는 "드레인이 장벽에 영향을 안 준다"는 가정에서 유도되므로 **60과 비교 가능한 건 SSlin뿐**
- **조치**: 게이트 제어=`SSlin`, 누설=`Ioff`, 드레인 영향=`DIBL` 로 셋을 분리. `analysis/config.yaml` map 에 SSlin/VtiLin/gmLin/IdLin_norm 추가, `build.py`에 DIBL 자동계산 추가
- **DIBL은 새 시뮬레이션 없이 기존 데이터로 계산 가능**했고(=(\|VtiLin\|-\|VtiSat\|)/ΔVd), FR 따라 5개 Ge% 전부 단조 증가(79→129 mV/V). 지금까지 "gm은 포화했는데 Ion만 오르는 건 Vt 롤오프 때문"이라고 **추론**만 했던 걸 직접 지표로 **입증**
- 물리적 원인도 스크립트에서 특정: 리세스 식각이 `replace.materials={Oxide SiStop}`으로 **관통 방지층(ChStop)을 함께 제거**한다. FR=35nm는 fin 전체 높이와 같아 스토퍼가 사라지고 p+ SiGe가 그 자리를 채워 관통 경로가 열림
- **기존 오류 정정**: `runs/attachments/G50_F0/notes.md`에 "게이트 재질이 없어서(`gate_material_present:false`) SS가 높은 듯"이라고 적혀 있었으나 **오류**. `finfet_sprocess.scm`에 GATEox/HfO2/Tungsten RMG 흐름이 전부 있고 SDevice가 쓰는 `n@node@_e`에도 게이트 스택 완비. 게이트가 없던 건 중간 저장 노드(`_GateRemoval`)를 본 것으로 추정

- "핀이 어디서 끝나고 기판이 어디서 시작하는지"를 도핑 색(NetActive)만으로 구분하려다 착각 — 채널과 기판이 배경 도핑 농도가 비슷해서 같은 색으로 보였던 것. Oxide(STI) 재질만 단독으로 켜서 그 윗면 높이로 핀/기판 경계를 다시 확인
- SiGe 재질만 켜고 봤을 때 "채널(ChFin)도 SiGe 아니냐"는 오해가 발생 — Materials 탭(재질 단위)과 Regions 탭(스크립트가 이름 붙인 세부 영역 단위)을 혼동한 게 원인이었음. Regions 탭에서 ChFin만 단독으로 분리해서 켜보니 정상적으로 n형 Silicon(Nch 수준)인 것으로 확인, 오해 해소
- S/D 도핑도 처음엔 "표면 근처만 고농도, 몸통은 배경 수준"이라고 잘못 판단 — 이것도 ChFin(채널)이 같은 화면에 섞여 있어서 생긴 착시였고, SDepi(S/D)만 따로 분리해서 BTotal·BActive를 보니 부피 전체가 균일하게 2e20으로 정상
- `finfet_sprocess.scm` 원문을 직접 읽고 리세스(FR)·언더컷(Esd) 식각이 실제 물리 기반 식각 모델이 아니라, 이상적인 사각 형상을 그대로 치환하는 기하학적 방식으로 구현돼 있음을 확인 — 실제 식각 프로파일(경사면 등)은 반영 안 됨
- Esd를 "채널 아래로 파고드는 것"으로 착각했다가, brick 좌표를 직접 계산해서 "핀 전체 높이에 걸쳐 균일하게, 채널 길이 방향으로만 7.5nm 옆으로 파고드는 것"이고 게이트 바로 밑 25nm 채널 자체는 (Esd < Lsp0라서 0.5nm 여유를 두고) 안 건드린다는 것으로 정정
- GeTotal 스칼라를 평면 컷(cutline)으로 잘라서 Ge=0(채널) 구간의 실제 폭을 측정 — 계산값(L+2·Lsp0-2·Esd ≈ 26nm)과 실측(~20~25nm)이 비슷해서, 이전에 3D 비스듬한 뷰에서 "너무 얇아 보였던 것"은 원근 왜곡 때문이었다고 결론
- STE 정규화 방법(채널 인접 지점, GPa 환산 방식) 초안 제안: 게이트 산화막 계면 × 채널 길이 중앙 × 핀 중심선(Y=0) 지점에서, StressEL 세 성분 중 채널 방향(길이 방향) 성분 하나만 사용 — 팀 확정 대기
- Strain_Impact=1 vs 0 SWB 비교 CSV(G50_F0, Ge=0.50/FR=0)로 최종 판정: IdSat_norm +227%(1.704e-4→5.574e-4), IdLin_norm +176%, gmSat +116%, |VtiSat| −23%(0.525V→0.403V), SSSat 549.8→183.5. 방향성(Ion↑, |Vth|↓)이 eSiGe pMOS 문헌(압축응력→정공 이동도 증가, 밸런스밴드 효과로 |Vth| 감소)과 일치 — 응력→전기 결합이 실제로 작동함을 확인

### 결정 사항

## 2026-08-05 — 방법론 전환: 결함 경계(People-Bean/Luryi-Suhir) 폐기 → Stress Transfer Efficiency(STE)로 재전환

### 한 일
- 전날(08-04) 확정한 "Ge%×리세스 깊이 → 결함 발생 경계(trade-off boundary) 지도" 방법론을 실제로 검증하기 위해, People-Bean(1985)/Luryi-Suhir(1986) 임계두께 근사식에 baseline 실제 치수(fin 반폭 7.5nm)를 그대로 대입해 계산
- 계산 결과 Ge 42~100% 전 구간에서 임계두께가 "무제한 보호"(문헌상 결함이 생기지 않음)로 나옴 — 즉 우리가 스윕하려는 Ge%×FR 범위 안에서는 결함 경계선 자체가 그려지지 않는다는 뜻. fin이 너무 좁아 탄성 완화가 결함 없이도 응력을 다 흡수해버리는 영역이라, "경계 지도"라는 결과물 형태 자체가 성립하지 않음을 확인
- 방법론을 결함 안전성(경계가 어디인가)에서 **응력 전달 효율(Stress Transfer Efficiency, STE)** — 채널에 실제로 전달되는 응력이 Vegard's law 명목 응력 대비 얼마나 되는가로 전환
- `finfet_sde.scm` → `finfet_sprocess.scm`로 재명명 (SDE 단독이 아니라 SProcess 흐름을 쓴다는 걸 이름에 반영)
- **FR(리세스 깊이) 변수를 스크립트에 신규 도입** — 원본 예제(FinFET_14nm)에는 없던 변수. fin 바닥 아래로 SiGe가 추가로 파고드는 깊이를 조건부 리세스 식각 로직(FR>0일 때만 실행)으로 구현. FR=0 조건에서는 원본과 동일한 구조가 나오는지 회귀 테스트로 확인(통과) — FR>0 실제 실행 검증은 아직 안 함
- `params.yaml`의 geometry/materials 항목을 실제 예제를 열어 확인한 값으로 채움 (Gate length 25nm · Fin height 35nm · Fin bottom width 15nm(반폭 7.5nm) · Fin pitch 48nm · GeMoleFraction 공칭 0.50 등)

### 결정 사항
- 결함 경계(People-Bean/Luryi-Suhir) 프레이밍 폐기 확정. **Stress Transfer Efficiency(STE)를 새 핵심 질문으로 채택** — "Ge%×FR을 스윕했을 때 채널에 실제로 전달되는 응력이 명목 응력 대비 얼마나 되는가"
- 결과물 형태는 그대로 유지 — 여전히 1차원 그래프 두 개가 아니라 Ge%×FR 2차원 지도. 다만 지도가 담는 값이 "결함 발생 여부"에서 "응력 전달 효율(%)"로 바뀜
- FR(리세스 깊이)은 원래 스크립트에 없던 변수를 새로 추가한 것이므로, 이 축 자체가 이번 프로젝트의 핵심 기여 포인트임을 재확인

### 막힌 점 / 리스크
- 임계두께 계산을 손으로 다시 검산한 것은 아니라 완전히 정량적으로 재확인된 것은 아님 — 다만 "전 구간이 무제한 보호로 나온다"는 방향성 자체는 명확해서 프레이밍을 바꿀 근거로는 충분하다고 판단
- FR>0 리세스 로직은 아직 회귀 테스트(FR=0)만 통과했고 실제 Sentaurus 실행으로 검증되지 않음
- STE의 정확한 정규화 방법(채널 어느 지점/영역 기준으로 잴지)은 이 시점엔 아직 확정 전 — 다음 날(08-06) 체적평균 방식으로 우선 채택, 이후 계면 단일점과 비교하며 provisional로 재조정됨

### 다음 할 일

- [ ] FR>0 리세스가 의도대로 파이는지 실제 Sentaurus 실행으로 검증
- [ ] `competition/README.md` 등 문서 전체를 새 STE 프레이밍으로 갱신

## 2026-08-04 — 주제 전환: DRAM BCAT DBCAT(질화막 두께)×접합 도핑 → FinFET + Embedded SiGe Source/Drain 응력공학

### 배경
- 실제 2025/2026 POLARIS SIF 수상작(아이디어·작품 부문) 6건을 팀이 직접 분석
- 그 중 **김나박구팀(2026 작품 부문)**이 이미 "BCAT + DWMG"로 우리가 하려던 것과 유사한 조합을 출품했음을 확인 — DBCAT×접합 도핑 조합의 독창성이 약해짐
- "~ 최적화가 아니라 기존 구조 + 새 공정 → 개선"이라는 팀의 핵심 요구사항을 재확인, 이 기준으로 대체 주제를 재검토

### 검토한 대안과 기각/채택 경위
1. **GAA 나노시트 dog-bone 접합 구조** — 검토했으나 "시뮬레이션하기 너무 어렵다"는 판단으로 기각
2. **NCFET/강유전체 게이트 스택** — 분석한 수상작 6건 중 3건이 이미 "특수 게이트 물질 삽입" 패턴이라 겹침 위험 판단으로 기각
3. **FinFET + Embedded SiGe Source/Drain 응력공학 (채택)** — FinFET 소스/드레인을 선택적 에피택시(SEG)로 SiGe 대체, in-situ 도핑, PMOS 채널에 압축 응력 유도. 스윕 변수: Ge 조성(%) × 리세스 깊이. 결과물은 단일 최적점이 아니라 두 변수의 트레이드오프 경계(전위결함으로 응력 이득이 무효화되는 지점) 지도

### 결정 사항
- 최종 주제: FinFET + Embedded SiGe S/D 응력공학, 스윕축 Ge%×리세스 깊이, 결과물은 결함 발생 경계(trade-off boundary) 2차원 지도
- 방법론: Sentaurus로 (Ge%, 리세스 깊이) 전 구간의 응력·이동도를 완전정합(pseudomorphic) 가정 하에 계산 → 문헌 기반 임계두께 경계선(People-Bean 1985 / Luryi-Suhir 1986)을 등고선 위에 별도로 오버레이하는 하이브리드 방식 (Sentaurus 자체는 결함을 반영하지 않는다는 것을 항상 전제)
- **팀 협업 방식을 대시보드 기반으로 전환**: 실제 작업용 저장소 [`ryu980920/Share`](https://github.com/ryu980920/Share)를 신설하고, GitHub Pages 대시보드([`https://ryu980920.github.io/Share/`](https://ryu980920.github.io/Share/))를 만들어 담당 과제·진행 체크리스트·소자 사진/메모·결과 CSV를 팀원 3인이 한 화면에서 공유·갱신할 수 있게 함. 정적 페이지라 체크박스/업로드가 그냥은 저장되지 않는 한계를, GitHub REST API를 브라우저에서 직접 호출(개인 Personal Access Token을 브라우저에만 저장)하는 방식으로 해결 — 팀원이 git 명령어를 몰라도 체크·사진 업로드가 실제로 저장소에 커밋되도록 구현함. 이 레포(`competition`)는 여정·의사결정 기록용이고, `Share`는 실행·결과 공유용으로 역할을 분리함
